# 本地录音删除修复与排查

## 修复范围

- `wx.saveFile` 保存的录音使用 `wx.removeSavedFile` 删除；未保存的临时录音使用 `FileSystemManager.unlink`。
- 文件已保存、索引写入失败的会话记录也按“已保存文件”删除，不根据 `recoverable=false` 误判为临时文件。
- 删除报错后重新检查存在性：只有确认文件不存在才收敛成功；权限、IO、未知错误保留引用供重试，不换接口强删。
- 文件已删但索引写入失败时，移除失效卡片并保留 dirty 标记，后续清理/变更补写索引。重启时也通过存在性检查清理失效引用；不自动删除仍存在的录音。
- 索引读取失败时不改写持久索引，但允许删除当前会话明确持有的临时录音。
- 删除确认框期间起进行同一录音互斥，用户取消或分享处理中不删除；意外异常在页面收口。
- 不改云端分享/过期策略，不迁移、不清空用户数据。测试只操作内存假文件，不删除实际录音。

## 控制台排查

微信开发者工具点击“编译”，打开“调试器 → Console”，筛选 `[recording]`，保留 Info 和 Warning 级别。诊断写入控制台，不另外落盘或上传；页面不显示内部错误。

| 日志 | 含义 |
| --- | --- |
| `delete.start` | 已确认删除，进入仓储 |
| `delete.file.saved.*` / `delete.file.temporary.*` | 缓存文件/临时文件删除接口阶段 |
| `delete.access.failed` | 不能确认文件存在性，保留录音 |
| `delete.file.failed` | 无法确认删除完成，保留录音 |
| `delete.metadata.pending` | 文件已删除，索引等待补写 |
| `delete.success` / `delete.already_removed` | 删除完成/重复操作已收敛 |
| `delete.cancelled` / `delete.blocked_sharing` | 用户取消/分享过程中禁止删除 |
| `delete.unexpected.failed` | 页面捕获未预期异常 |
| `save.file.*` / `save.fingerprint.failed` | 保存文件和读取最终文件信息 |
| `metadata.read.failed` / `metadata.write.failed` | 索引读写异常 |

每条日志仅含阶段、时间、必要时的短录音编号、原生错误码与分类（权限不足、空间不足、文件不存在、文件忙、超时、接口不支持、IO 或未知）。不打印原始错误对象、录音内容、完整路径、分享链接或凭证。日志接口本身故障不能影响录音操作。

## 验证与边界

- 新增回归先观察失败，再修复：缓存删除接口、原生异常、文件消失竞态、索引删除误报、索引不可读时临时录音删除。
- 运行时测试补充：重启后删除、权限/IO拒绝、未保存临时文件、保存成功索引失败、隐私脱敏、控制台异常。
- 页面测试补充：成功/失败、异常捕获、连续点击、取消、分享互斥，以及本地删除不调用云端删除。
- 30 项脚本回归、兼容参数类型检查、修改源文件 ESLint 和微信小程序构建通过。构建第一次停在初始化，停止本次构建进程后，使用 `npm run build:weapp` 重跑通过；未清理用户缓存。仍有既有 Browserslist、Sass 和包体建议警告。
- 独立审查发现并修复了“索引读取失败阻止临时录音删除”的边界问题。

尚未从用户设备获得原始原生错误，也未执行真机删除。上述文件 API 限制由平台边界 mock 复现，不将其描述为已在用户真机确认的唯一根因。

验收时请新录两条无须保留的短录音，只删除其中一条，检查另一条仍能回听；返回再进入列表确认已删项不再出现。分别在模拟器、手机和 iPad 执行。若失败，提供同一次操作的 `[recording]` 日志即可，不要清缓存或提供录音文件。
