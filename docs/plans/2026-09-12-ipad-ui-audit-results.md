# 手机与 iPad 全页面 UI 复核记录

日期：2026-09-12。分支：`codex/ipad-ui-navigation-audit`，起点 `89534f5`。本轮修复界面和导航，不修改录音状态机、音频素材映射、云函数或本地存储实现；未推送、合并、部署或清除用户缓存。

## 结论与根因

截图中的底栏遮字不是单纯模拟器显示问题：真实 Taro UI 图标将 `size=24` 转为 `48rpx`，在 768px 宽窗口里约为 49px，而原 Pad 底栏只有 56px 高。图标、文字和内边距放不下。旧视觉测试将图标简化成固定 px，因此漏报。

现已用真实 AtIcon、真实 Taro 尺寸转换、实际打包 WXSS 重现并修复。首页按钮原来的灰圆属于微信原生导航外观，不是页面里的 box-shadow；打卡页改为轻量自定义导航，保留系统胶囊，首页入口采用无底色、无边框、无阴影的房子图标。

## 逐页检查

| 编号 / 页面 | 已处理的问题 | 验证重点 |
| --- | --- | --- |
| 1 首页 | 图标随 Pad 宽度放大；底栏文字被挤出；图标自身多算一份文字间距 | 图标固定 px，底栏基高64px加安全区，标签12px/16px行高，正文预留76px加安全区 |
| 2 教材书库 | 保留左右留白和现有列表；空态标题/说明在 Pad 上过大 | 搜索、筛选和23本真实封面；窄分屏可横滑筛选；空态字号固定，不显示重复“可跟读”标签 |
| 3 跟读教材 | 压缩样式使左右 padding 失效；短 Pad 窗口的目录滚动区越界 | 常态、录音、暂停、保存成功、保存失败、目录、无效教材；目录头不缩，滚动区占剩余高度 |
| 4 打卡/回听 | 纯图标首页入口；加载/错误时导航被正文居中；横屏刘海遮返回按钮；错误说明比标题还大 | 三态导航均在正文外；返回保留页面栈；安全降级；播放时显示当前/总时长；离页停止播放 |
| 5 我的录音 | Pad 预览只限 width、未限 flex-basis，图片槽过宽；横屏空态按钮落到首屏外 | 封面槽固定88px，图片完整适配；父子纵向flex正确分配空间；横屏紧凑空态；本地记录在云列表失败时仍可见 |

三个页面的留白问题有共同原因：未保护的 `constant()` 被 cssnano 合并到整条 padding shorthand，运行时不支持该函数时，左右留白也一起失效。现保留有效数值回退，并把旧版 constant 与现代 env 分别置于对应 `@supports` 内。

所有受检主要操作区至少44×44 CSS px。未改变教材热点的坐标和图片比例，也未给普通跟读/回听引入上传动作。

- 使用真实页面组件设置场景。保存成功和失败分开断言，播放场景必须出现 `0:03`；不会把普通首屏误算成录音/播放态。

- 变更文件 ESLint通过；兼容 TypeScript 检查通过：`tsc --noEmit --skipLibCheck --noUnusedLocals false --noUnusedParameters false`。默认严格命令仍有既有未使用声明和第三方类型冲突，本轮没有隐藏或修改这些问题。
- 微信小程序构建通过（项目已禁用持久构建缓存）。仍有既有 Browserslist 数据过期、Taro UI Sass 弃用和包体建议警告；没有为消除提示而升级依赖。
- 两轮任务级独立复核及全分支独立复核已通过；最终复核范围 `89534f5..55aa5e5`，没有需本轮修复的 Critical / Important / Minor 发现。
