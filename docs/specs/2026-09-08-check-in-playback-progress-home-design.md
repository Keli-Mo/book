# 分享页播放进度与首页入口设计

## 背景与根因

微信开发者工具最后打开的工作目录是 `haisha-multibook-home`。该工作树仍停留在旧提交，只渲染录音总时长；主工作树 `haisha` 已包含 `onTimeUpdate`、当前播放位置状态和“当前 / 总时长”渲染逻辑。因此，真机预览使用的是旧构建产物，并非用户操作错误。

## 目标

- 未播放时继续只显示录音总时长，例如 `0:08`。
- 播放开始后显示当前进度和总时长，例如 `0:03 / 0:08`。
- 停止、播放结束、播放失败或页面离开后，恢复只显示总时长。
- 在系统导航栏提供快速回到小程序首页的入口。
- 保留现有分享、录音播放和“我也来跟读”流程。

## 方案

### 播放进度

保留当前 `isPlaying` 条件：只有播放中才显示“当前 / 总时长”。页面通过 `InnerAudioContext.onTimeUpdate` 读取秒单位的 `currentTime`，转换为毫秒、向下取整并限制在录音总时长以内，再交给统一的时长格式化函数显示。

为避免测试只检查源码中是否出现了两个函数名，将最终显示文本抽成纯函数并直接测试：未播放返回总时长，播放中返回“当前 / 总时长”。页面必须调用该函数，避免渲染分支与测试脱节。

### 顶部首页入口

在 `CheckInDetail` 页面配置中启用微信原生 `homeButton`。页面继续使用系统导航栏，不自定义状态栏、返回按钮或胶囊避让。该方案能把首页入口放在顶部，并避免内容区新增重复按钮。

### 工作目录同步

实现与验证以 `master` 主工作树为准。完成后将微信开发者工具当前使用的 `codex/multibook-home` 工作树安全快进到同一提交；只同步 Git 跟踪内容，不修改或提交该工作树已有的本机 `project.config.json`、`project.private.config.json` 配置。

## 错误与生命周期

- 音频错误时停止播放状态、清零当前进度并保留现有失败提示。
- 页面隐藏时停止录音播放、清零当前进度。
- 播放结束或用户主动停止时恢复未播放显示。
- 首页入口由微信原生导航处理，不依赖页面栈，避免分享直达页面无法 `navigateBack` 的情况。

## 验证

- 回归测试验证未播放与播放中的最终时长文本。
- 回归测试验证页面接入实时进度并启用 `homeButton`。
- 运行音频、打卡及界面相关测试、业务类型检查和微信小程序构建。
- 微信开发者工具中重新编译后进行真机冒烟测试：播放时进度递增，停止后恢复总时长，顶部首页按钮可回到首页。

## 非目标

- 不改为始终显示 `0:00 / 总时长`。
- 不实现拖动进度条、暂停续播或自定义导航栏。
- 不改变录音上传、分享鉴权或云数据库结构。
