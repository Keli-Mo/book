# 全教材、全机型与录音可靠性设计

日期：2026-09-09
状态：用户已批准方案 1（统一训练引擎 + 响应式布局）

## 1. 目标

将现有只开放 1 本教材的听力跟读流程扩展为 23 本教材共用的一套训练引擎，并保证在手机、iPad 和 Android 平板的横竖屏中可以稳定完成以下闭环：

1. 从首页或书库进入任意教材。
2. 目录只列出含示范音频的训练页，选择后准确显示对应教材图片。
3. 音频热点始终落在教材图片的对应位置，图片缩放、横竖屏切换后不漂移。
4. 用户可播放示范音频，同时开始、暂停、恢复和结束自己的跟读录音。
5. 用户可回听录音，弱网下获得明确状态，成功后生成一次打卡记录。
6. 打卡详情和分享页面展示正确教材、章节、教材页、录音时长与播放进度。

## 2. 已确认的产品边界

- 共接入书库当前列出的 23 本教材（ID 3–25），不新增教材系列。
- 不恢复“完整教材连续翻阅”入口；训练列表只包含有音频的教材页。
- 不增加独立音频入口；示范音频继续绑定教材页热点。
- 分享内容是用户本次录音和打卡记录，不包含题目、答案或教材原音。
- 无音频的教材页不生成训练项。
- 关键业务代码保留必要中文注释，Git 提交使用英文 Conventional Commit 前缀和中文说明。

## 4. 总体架构

### 4.1 通用教材训练模型

用通用的 `bookPractice` 模块替代只绑定教材 ID 3 的 `book3Practice`：

```ts
type BookPracticeBundle = {
  book: BookCatalogItem;
  coverUrl: string;
  practices: ListeningPractice[];
};

function buildBookPracticeBundle(bookId: string): BookPracticeBundle | null;
```

构建过程只读取现有三张总表：

- `concatImages[bookId]`：教材图片。
- `allAudioList[bookId]`：按真实教材页号组织的音频与热点坐标。
- `catalogLists[bookId]`：目录分组。

路由统一改为：

```text
/pages/Practice/Practice?bookId=<ID>&practice=<训练索引>
```

缺少、非法或尚未加载成功的 `bookId` 必须展示可恢复错误页并提供返回书库入口，不能静默回退到第 1 本教材。

所有现有入口都必须显式传递教材：

| 入口 | `bookId` | `practice` |
| --- | --- | --- |
| 首页“继续跟读” | 首页当前教材；本期默认 ID 3 | 0 或已保存进度 |
| 书库教材行 | 被点击教材 ID | 0 |
| 空打卡页“开始第一次跟读” | ID 3 | 0 |
| 打卡详情“我也来跟读” | `detail.bookId` | `detail.practiceIndex` |

历史记录缺少合法 `bookId` 或训练索引时，不猜测教材；按钮改为“选择教材”并进入书库。

### 4.2 页面、音频与热点的唯一对应关系

真实教材页号从图片 URL 去除查询串、解码后，以 `_(\d+).(png|jpg|jpeg|webp)` 文件名结尾解析，不使用“图片索引 + 常数”的猜测方式。ID 11–14 仅允许数组索引 0 的封面无法解析页号；其他无法解析或重复页号均为构建失败。`imageIndex` 只能来自 `concatImages[bookId]` 的实际数组位置。每个训练项同时保存：

- `bookId`
- `imageIndex`
- `pageNumber`
- `imageUrl`
- `sectionTitle`
- 当前页全部音频热点

热点坐标统一转换为相对于教材图片实际渲染盒子的百分比。训练页必须采用 `widthFix + width: 100% + 自然高度`，热点层 `inset: 0` 覆盖同一个实际图片盒子，不允许外层固定高度产生 letterbox。打卡详情和列表中的教材内页快照统一使用 `aspectFit`；该限制不适用于纯封面装饰图。

三类历史坐标继续由唯一的 `parseTrackCoordinate` 转换：默认和 `Cambridge` 只接受有限数值，`Percentage` 接受有限数值或严格的 `%` 数字字符串。视觉圆点可小于 44px，但透明交互外壳不得小于 44px；边缘坐标按实际图片宽高和 22px 点击半径动态收敛，批量验证报告列出教材、页码、音频序号和原坐标。

`catalogLists[id].page` 的既有语义固定为 `concatImages[id]` 的零基数组索引，不是教材真实页号。目录必须按 `page` 升序且不得重复或越界；训练归属采用“当前位置之前最近的目录项”。首个目录项之前的音频归为“课程导入”。没有音频的目录区间允许存在，但验证报告必须列为提示而非失败。

### 4.3 打卡数据

新打卡记录必须写入实际训练上下文，禁止继续使用固定教材 ID 或固定教材名称：

```ts
type CheckInContext = {
  bookId: string;
  bookTitle: string;
  practiceId: string;
  practiceIndex: number;
  pageNumber: number;
  imageUrl: string;
  sectionTitle: string;
};
```

“我的打卡”和分享详情直接读取记录快照。即使后续教材标题或目录调整，历史打卡仍显示创建当时的教材和页码。旧记录缺少新字段时按宽容读模型展示已有快照，并返回 `canRestart: false`；不得因为增加 `requestId`、`status` 等字段而让旧记录无法查看。

## 5. 手机与 Pad 响应式设计

### 5.1 设备分类

适配层产出单一纯函数合约 `DeviceLayoutInput → DeviceLayoutProfile`，输入窗口尺寸、屏幕尺寸、安全区和可选设备类型；组件订阅 `onWindowResize` 并在卸载时解除。正式支持手机、iPad 和 Android Pad；桌面微信只要求不溢出、不白屏，不纳入录音承诺。

判定规则（尺寸均为 CSS px）：

1. `isPad = deviceType === "pad"`；设备类型缺失时，以屏幕短边 `>= 600` 作为回退。
2. `orientation = windowWidth > windowHeight ? "landscape" : "portrait"`。
3. `split = isPad && orientation === "landscape" && windowWidth >= 960 && windowHeight >= 600`。
4. 其他情况均为单栏；横屏手机即使宽度超过 768 也保持单栏。

固定样例：320×568、430×932、844×390 手机为单栏；768×1024、800×1280 Pad 竖屏为居中单栏；1024×768、1280×800 Pad 横屏为双栏。Pad 分屏窗口不足双栏阈值时自动退回居中单栏。

### 5.2 布局规则

- 手机竖屏：沿用单栏阅读，教材图、录音卡和翻页按钮纵向排列。
- 手机横屏：内容宽度受限并保持可滚动，不把教材图压缩到不可读。
- Pad 竖屏：主体居中，最大宽度 820px；字号和按钮不随 `rpx` 无限放大。
- Pad 横屏：主体最大宽度 1280px，教材列最小 480px、操作列最小 320px、列间距 24px；不满足任一最小值就退回单栏。目录改为宽侧栏，录音控制保持在可见区域。
- Home、BookLibrary、Practice、CheckInDetail、MyCheckIns 五页都设置内容最大宽度；书库和打卡列表在 Pad 宽窗口可用双列卡片。
- 固定栏使用 `padding-bottom: calc(12px + constant(safe-area-inset-bottom))` 后再以 `env()` 覆盖；普通滚动页末尾使用 `calc(24px + safe-area-inset-bottom)`。API 没有 `safeArea` 时 inset 按 0，状态栏缺失时取 20px，自定义导航胶囊无效时使用 44px 导航高度。
- 所有按钮和热点交互外壳明确设置 `min-width/min-height: 44px`；系统字体放大或 320px 窄屏放不下两个按钮时纵向排列。
- 图片完整显示，书名和章节长文本按字段使用单行省略或两行截断。
- Taro 源 SCSS 中需要固定为 CSS 像素的尺寸必须使用大写 `PX`，例如 `44PX` 编译后保持为 `44px`；小写 `px` 会参与单位转换并变为 `rpx`。运行时 React inline style 不经过该转换，可使用 `` `${value}px` ``。布局常量、44px 命中区、Pad 最小列宽和间距都遵守这一规则。

### 5.3 旋转和尺寸变化

窗口变化后只更新布局分类，不重建当前录音或播放对象。旋转期间：

- 当前教材、训练索引和目录位置不变。
- 正在播放的音频不因纯布局旋转而重启。
- 正在录音的状态和累计时长不丢失。
- 图片完成重新布局后，热点按百分比自然跟随，不做像素坐标重算。

## 6. 录音可靠性设计

### 6.1 状态机

录音先经过能力检测，再使用以下显式状态：

```text
checking → unsupported
        ↘ idle → starting → recording ⇄ paused → stopping → recorded → uploading
                              ↘ error       ↗                  ↘ error
```

`unsupported` 只能在重新检测能力后离开。所有按钮行为先通过纯函数状态策略判断，避免快速连点造成重复 `start`、`pause`、`resume` 或 `stop`。只有原生回调确认后才进入相应稳定状态。

每次开始录音生成新的 `recordingSessionId` 和递增 `operationSeq`。所有待处理原生动作记录会话和序号；回调只有匹配当前会话且组件仍挂载时才能提交状态。`stopping` 中迟到的旧 `onError` 只记录诊断，`starting` 收到不属于当前会话的 `onStop` 必须丢弃，切换训练或卸载后到达的回调不得覆盖新录音。

### 6.2 能力与权限

- 初始化前检测 `getRecorderManager`、`pause`、`resume` 及中断监听能力。
- 不支持录音的微信版本显示升级提示，不白屏。
- 支持开始/结束但不支持暂停的环境隐藏暂停按钮，并明确提示降级行为。
- 首次拒绝、永久拒绝、系统级麦克风关闭均提供可恢复路径。
- 错误弹窗保留微信原始错误和错误码，不把所有失败都归因为权限。

### 6.3 系统中断与生命周期

监听 `onInterruptionBegin`、`onInterruptionEnd`、页面隐藏和页面显示，并记录 `pauseReason: "user" | "background" | "interruption" | null`：

- 来电、微信语音/视频或系统抢占时立即暂停界面时间线。
- 中断结束后绝不调用 `resume()` 自动继续录音；仅提示“录音已中断，请手动恢复”，由用户点击“继续录音”。若原生层已结束录音，仍以有效 `onStop` 结果进入 `recorded`，不伪造可恢复状态。
- 页面进入后台时，先冻结 JS 时间线，再尝试 `recorder.pause()`；收到 `onPause` 后进入 `paused/background`。若 `pause()` 抛错或 1 秒内无回调，等待 `onStop/onError`，同时返回页面时显示“正在确认录音状态”，不允许继续或上传。若原生已停止，以有效 `onStop` 结果进入 `recorded`；否则终止本轮并保留明确错误。
- 若原生层直接结束录音，则以 `onStop` 返回的文件和时长为准进入 `recorded`。
- `onError`、异常 `onStop` 和组件卸载都必须清理待处理动作和计时器。

### 6.4 示范音频与录音并行

允许录音期间播放、暂停和切换当前教材页的示范音频。两条链路使用独立上下文：

- 页面切换、训练切换时停止示范音频。
- 不因停止示范音频而调用或重建全局录音管理器。
- 真机重点验证 iOS 静音键、扬声器、蓝牙耳机和 Android 音频焦点。
- 扬声器播放的示范音频可能被麦克风一并录入，这是“跟读录音”的预期行为；使用耳机时应尽量只录入用户声音。蓝牙断连或音频焦点被抢占时允许示范音频停止，但录音状态必须进入可解释的暂停或结束状态，不能继续假计时。

### 6.5 文件与上传

- 最低微信基础库版本为 **2.3.0**。录音使用 `sampleRate: 16000`、单声道 `numberOfChannels: 1`、`encodeBitRate: 48000`、`format: "mp3"`；五分钟 MP3 约 1.8MB，作为离线容量估算值，不替代原生文件大小。
- `onStop` 的原生 `duration` 与 `fileSize` 是时长和容量记账的唯一权威值，不能用 JS 计时器推算或覆盖。收到有效 `onStop` 后先调用 `saveFile`；保存成功即刻把内存状态、`PendingCheckIn.localPath` 和后续上传 `filePath` 切换为回调给出的 `savedFilePath`，不得继续使用临时路径。
- 微信持久化本地文件总额最多 10MB。离线 `PendingCheckIn` 队列最多保留 3 条，且已保存文件合计不超过 `8 * 1024 * 1024` 字节（8MiB），为其他小程序持久化文件预留空间；每条记录持久化原生 `fileSize`，以便精确计算队列总量。
- 启动、创建新录音前和 `saveFile` 前都清理超过 7 天或已找不到本地文件的记录；`saveFile` 因配额满失败时，先执行该清理并只重试一次。若新文件仍会超过 3 条或 8MiB，不能静默删除仍可恢复的待上传录音：提示“离线录音已满（最多 3 条、8MiB），请清理历史录音或联网提交后再保存”。用户确认删除指定旧项后才删除其本地文件和记录。当前临时文件仍可即时回听/上传，但标记 `recoverable: false`，并提示“关闭小程序后可能无法恢复”。
- `requestId` 在录音成功后生成，格式为 32 位十六进制随机值，同一待上传录音的所有重试必须复用。相同 ID 但训练快照或录音摘要不一致时服务端返回冲突。
- 上传使用微信云存储 callback 形式的 `Taro.cloud.uploadFile`（底层 `wx.cloud.uploadFile`），取得云存储 `UploadTask` 后注册 `onProgressUpdate` 展示百分比，并保存任务以支持用户取消时调用 `abort()`；无进度事件时显示不确定进度。服务端 `prepare` 返回确定性路径 `checkins/<openid-hash>/<requestId>.mp3`，所有重试都上传到同一 `cloudPath`。网络错误最多自动重试 2 次（1 秒、3 秒退避），之后保留待上传项供用户手动重试。
- 云函数用 `sha256(openId + ":" + requestId)` 派生确定性记录 `_id`，在数据库事务中读取并创建。重复请求且载荷摘要相同，返回原 `id/shareToken`；摘要不同返回冲突。旧记录没有 `requestId/status` 时按 `created` 读取。
- 上传成功后先持久化 `cloudFileId` 再创建记录；直到 `commit` 明确成功前始终保留 `savedFilePath` 和待上传记录。创建响应不确定、上传被取消或网络失败时，用同一 `requestId`/`cloudPath` 重试，绝不立即删除。只有服务端明确拒绝且确认未建记录时才清理文件。
- 删除先把本人记录标记为 `deletePending`，随后删云文件，再删数据库记录；任一步失败都允许同一删除请求重试。`deletePending` 不出现在普通列表，详情显示“正在删除”，旧记录缺 `status` 按 `created` 处理。

## 7. 批量素材验证

本地快速验证必须覆盖 23 本，而不是只检查 ID 3：

1. 每本书在目录、图片、音频三张总表中均存在。
2. 图片真实页号不重复；无页号封面只能出现在允许的教材中。
3. 每个非空音频页都能找到对应教材图片。
4. 每段音频都有合法 HTTP(S) URL；默认/Cambridge 坐标为有限数值，Percentage 坐标为有限数值或严格 `%` 数字字符串。
5. 目录数组索引升序、唯一且落在图片数组范围；无音频目录区间只告警。
6. 输出每本书图片数、音频页数、音频段数和边界校正数。

远端验证作为发布前诊断单独执行，不进入每次本地单测。使用 GET + Range（不用可能被对象存储拒绝的 HEAD）、有限并发、超时、重定向和重试检查允许的腾讯云域名；报告区分对象不存在、权限配置和验证网络失败，只有重复确认的 404、权限拒绝或 URL 语法错误才记为素材阻塞。

### 8.1 自动化

- 通用教材模型：23 本均能构建；练习数量、真实页号和章节归属正确。
- 书架路由：所有教材传递正确 `bookId`，非法 ID 有错误页。

最低覆盖：

- Android 320px 左右小屏及主流大屏各一档。
- iPad 竖屏、横屏和旋转过程。
- Android Pad 竖屏、横屏和旋转过程。
- 微信当前稳定版，以及低于所需能力的降级模拟。

- 0.5 秒边界、暂停恢复、5 分钟自动停止、来电/微信通话中断、锁屏、后台。
- Wi-Fi、移动网络、断网重试和上传过程中切换网络。
- 本地回听、上传后本人回听和分享访客回听。

受限于自动化环境，来电、锁屏、蓝牙和不同实体设备必须由真机操作确认；代码完成时提供逐项点击清单，未获真机结果前不得声称覆盖所有实体机。

## 9. 提交与发布策略

在 `codex/all-books-device-recording` 隔离分支实施，按以下边界提交：

1. `docs:` 设计和实施计划。
2. `test:` 全教材映射失败测试。
3. `feat:` 通用教材训练模型与全部书籍路由。
4. `feat:` 手机与 Pad 响应式适配。
5. `test:` 录音兼容状态机失败测试。
6. `fix:` 录音中断、生命周期和本地文件保护。
7. `fix:` 上传与打卡幂等一致性。
8. `test:` 全链路回归与验收脚本。

每个提交均可独立回滚。最终先在隔离分支运行完整验证，再决定是否合并到开发者工具使用的工作树；不会覆盖 `project.config.json` 或 `project.private.config.json` 的本机配置。
