## 2. 必须先处理的问题

### P1：旧接口缺少文件归属校验，存在越权回听、删除风险

位置：[checkIn/index.js:193](E:/REPOSITORY/haisha/haisha/.worktrees/all-books-device-recording/cloudfunctions/checkIn/index.js:193)，关联详情签名、删除和仍开放的 `create` 分发入口。

旧 `create` 只判断录音 fileID 的格式和 `/checkins/` 路径片段，没有证明该文件属于当前调用者。知道他人旧文件 ID 的调用者，可以把同一文件挂到自己的记录下，再通过自己的记录获取回听授权或触发服务端删除。

两个独立内存验证均确认：直接读他人记录被拒绝；创建别名记录成功；没有原记录口令也能获得别名回听授权；删除别名会删除原文件、留下原记录。今天下载的线上源码与这段代码一致。

边界：这不是“可以随意枚举所有录音”；需要知道目标旧文件 ID。未验证真实播放 URL 是否能反推出该 ID，也没有证据表明已发生真实攻击。新版独立 `expiring-shares-v2/` 文件不能直接套用这个旧路径入口。

整改建议：优先停止不再需要的旧新增入口，或实施可信的文件归属授权；保留必要的合法历史读取。仅从客户端移除调用不够。关闭入口前还应审计已有旧记录是否存在同文件跨 owner 引用，避免只堵新增而遗漏既有别名。添加跨用户读、创建别名和删除的负向回归。

这是当前第一优先级，不应被 UI 美化或普通构建告警挤到后面。

### P2：云端删除失败后，用户可能失去重试入口

位置：[checkIn/index.js:253](E:/REPOSITORY/haisha/haisha/.worktrees/all-books-device-recording/cloudfunctions/checkIn/index.js:253)、[checkIn/index.js:284](E:/REPOSITORY/haisha/haisha/.worktrees/all-books-device-recording/cloudfunctions/checkIn/index.js:284)。

新版先标记 `deletePending`、再删除文件，这能防止迟到提交恢复旧分享。但一旦物理删除失败，列表刷新就隐藏该记录；清理程序又通常要等原期限到期才处理它。用户可能看不到记录，却仍有云文件占空间。

整改建议：为已请求删除但尚未完成的云文件保留可重试入口，或增加独立、安全的后台重试；区分“分享已失效”和“云文件已删除”。不能以卡片消失作为物理删除证据。

### P2：另一设备删除云分享后，原设备仍可能复用失效链接

位置：[CheckInDetail.tsx:213](E:/REPOSITORY/haisha/haisha/.worktrees/all-books-device-recording/src/pages/CheckInDetail/CheckInDetail.tsx:213)、[checkInSubmissionCoordinator.ts:240](E:/REPOSITORY/haisha/haisha/.worktrees/all-books-device-recording/src/features/listeningPractice/checkInSubmissionCoordinator.ts:240)。

建议提供用户主动触发的“重新生成分享”恢复路径，先确认旧状态，再安全创建新代；不能通过清缓存、删除本机录音或删除服务端防重记录来重置。

### P2：3 秒函数预算和清理游标存在规模化风险

位置：[cleanupExpiredShares/index.js:88](E:/REPOSITORY/haisha/haisha/.worktrees/all-books-device-recording/cloudfunctions/cleanupExpiredShares/index.js:88)、[checkIn/index.js:151](E:/REPOSITORY/haisha/haisha/.worktrees/all-books-device-recording/cloudfunctions/checkIn/index.js:151)。

清理每批最多 50 条，逐条串行执行，整页结束才保存游标。每个候选通常有两次事务及文件删除；已经删除的防重记录也会重复校验、删除和写状态。如果平台在游标落盘前硬超时，下次可能反复做同一页，后页无法及时推进。

当前两个函数超时均为 3 秒。不能断言现有少量数据必定超时，但分享提交会完整下载音频做校验，清理满批也明显需要专门测量。应测最大合法文件、冷启动、慢存储、满批、密集已删记录，确认耗时和游标进展，再确定批量与超时余量。只增加超时不能替代可恢复的进度设计。

不能删除防重记录来“加速”，它们用于阻止旧请求恢复已过期分享。当前 `deleted` 计数也可能包含重复处理，不等于本批新释放的文件数量或字节数。

## 4. 本地保存与云容量的真实边界

当前业务方向仍是：本地完成录音不自动上传；点击分享才上传；有效分享复用；新版分享提交成功起 30 天有效；云到期不删除本机文件。

本机容量配置是 100 MiB 管理预算，保留 10 MiB 余量，保存预算 90 MiB，开始录音时为最大 8 MiB 单文件再预留空间，所以已用门槛为 82 MiB。统计的是实际保存文件，包括未被列表索引引用的文件，不是整台手机剩余存储。

这些检查降低风险，但不是“绝不丢失”的担保：原生存储故障、索引写入失败、用户清除数据、卸载或设备损坏仍可能造成丢失。文件已移动而索引未落盘时，当前恢复信息可能只在会话里；杀掉微信后没有已验收的自动扫描找回入口。

未完成练习的草稿会在主动重新录制成功后被替换；已经完成的历史录音有保护。对用户说“不自动删本地”时，应区分主动重录替换与历史自动清理。

容量粗算，仅作场景估算，不是读取到的账单：

- 当前录音目标码率 48 kbps，约 0.36 MB/分钟，5 分钟约 1.8 MB；实际以文件字节数为准。
- 100 名学生，每天每人分享一条 5 分钟录音，保存 30 天，稳定期约 `100 × 1.8 MB × 30 = 5.4 GB`，还未加教材、未清理文件和数据库。
- 若仅 10% 的上述录音分享，约 0.54 GB。若每条被完整回听两遍，按 30 天估算的音频下行数据量约分别 10.8 GB / 1.08 GB，实际计费口径须看平台。
- 之前截图的 3 GB 不能替代今天的实际已用容量、余额、CDN 流量和套餐核验。因此不能直接保证“目前套餐肯定够用”。

云分享不是永久备份，也不是换机迁移：当前没有已验收的本地导出/导入能力。30 天过期控制也不能撤回接收者已经另存的副本。

## 6. 你需要亲自或配合复查的事项

### 真机验收

- [ ] Android 手机、iPhone、iPad 各至少一台；iPad 竖屏、横屏和可用时的分屏；字体放大后检查底栏、按钮和安全区。
- [ ] 分别录 1 秒、1 分钟、完整 5 分钟；多次暂停/继续；录音同时播放示范；对比界面时长和真实回听内容。
- [ ] 蓝牙/有线耳机与外放切换、来电/其他音频打断、切后台/锁屏、停止后立即返回。不要用唯一的重要录音做破坏性测试。
- [ ] 无网仍可本地完成和重启后回听；分享弱网/断网可恢复且不反复制造新上传。
- [ ] 在专用测试设备接近容量边界时检查是否提前阻止新录音，已保存录音是否仍可读；本轮未在真机灌满空间。
- [ ] 两个独立微信测试账号：合法朋友链接可听，无口令/错误口令拒绝；不能直接读写或删除他人的测试文件。
- [ ] 分享中返回并重进、分享云删后原设备恢复、旧链接过期、本地仍在、人工删除、慢列表刷新。相关已发现问题应修复后重测。
- [ ] 每个教材系列抽首、中、末训练页听音校对，不能只看图能打开。检查目录页号和音频热点是否对应原内容。

### 运营、隐私与授权

- [ ] 教材封面、扫描页和原音的授权范围是否包含小程序对外提供服务；拥有资料不当然等于具有对外网络传播授权。需你核对授权文件，不能仅凭程序能播放判断。参考：[《著作权法》](https://www.npc.gov.cn/c2/c30834/202011/t20201119_308796.html)。
- [ ] 微信后台隐私保护指引与实际录音/分享处理一致；麦克风拒绝后可理解、可恢复。不在代码里出现自定义隐私弹窗，并不能单独证明未适配，仍要核验后台配置和首次进入体验。参考：[腾讯云微信隐私适配说明](https://cloud.tencent.com/document/product/1301/97930)。
- [ ] 如处理不满 14 周岁学生的个人信息，确认监护人同意及专门处理规则。参考：[《个人信息保护法》第三十一条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。这是上线核对项，不是本报告已经完成的法律合规认定。
- [ ] 学生/家长是否理解：默认本机保存，分享才上传，链接有效 30 天，云到期不删本机；本地清除或换机不保证恢复。
- [ ] 分享凭证随链接携带，不需要用户手工输入，但链接被转发后持有者也可能访问。这不是“只有指定老师能听”。
- [ ] 老师怎样知道是谁交的？OPENID 识别微信账号，不自动等于学生实名，且家长账号可能对应多个孩子。初期可约定发送时备注学生代号，或另行设计最少必要的标识；不必立即增加复杂班级模块。
- [ ] 留一个可用的反馈/删除请求联系方式；发生文件丢失或链接泄漏时谁联系用户、谁处理控制台，要提前明确。
- [ ] 复查小程序主体、服务类目、备案/审核状态、隐私指引、合法域名及审核体验入口，最终以微信后台对本应用的要求为准。
- [ ] 核对当前套餐、真实已用量、余额、通知接收人和续费时间；教材与录音的容量/流量分开记录。
- [ ] 决定重要录音要保留多久、是否需要可控导出/迁移。若需要长期留档，当前 30 天分享不能承担此职责。

### 发版留档

- [ ] 记录实际上传目录、提交/变更清单、客户端版本、上传时间、云函数源码摘要及运行配置。
- [ ] 持有一个经过验收、兼容现有数据的回滚版本；不要把旧主目录等同于安全回滚包。
- [ ] 上线前关闭调试豁免，用体验版完成首次授权和好友分享流程。
- [ ] 合并本次新增反例到回归测试，再要求构建、标准类型检查、测试和人工清单通过；先前 40 项全绿只覆盖已有断言。

## 7. 建议执行顺序

1. 先修复旧 `create` 文件归属漏洞，同时补负向安全测试，核验已有旧记录引用。
2. 修复分享重入、云删除恢复、失效链接重建和慢列表刷新；保留本地文件优先原则。
3. 完成云权限、清理只读预演、满批性能及独立测试数据删除验收，确认后才启用生产自动清理。
4. 清理类型检查问题，固定发行源，核对隐私/教材授权/老师识别约定，完成手机与 iPad 真机测试。
5. 先用自有或已同意的测试账号小范围试用，再逐步放量；出现越权、录音实际丢失或清理异常就停止放量。暂不建议在这些门槛前继续扩展功能或做大范围 UI 改版。
