# 录音保存中断保护与最短发布验收

## 范围

用户已同意先补保存中断保护，并要求不要反复安排冗长测试。测试版清理验收停止：不删真实数据、不启用自动删除、不部署云函数、不上传或发布客户端。

只改本地录音保存与恢复。原主键 `pending-check-ins-v1`、原生 `wx.saveFile`、现有路径、100 MiB 管理预算和 10 MiB 安全余量不变。没有搬迁旧录音、新增自动上传或改 UI。

## 保存与重启处理

1. 原生保存返回真实路径后，先将该条录音及必要恢复快照写入独立本地日志 `pending-check-ins-v1-save-journal`，再读取指纹并写主索引。该日志不是音频备份，不包含第二份音频。
2. 主索引成功后尽力移除日志；失败保留当前会话重试和跨重启线索，不能虚报已安全保存。
3. 重启只处理日志明确记录的路径，检查文件存在、实际大小和指纹。新保存项没有主索引冲突才能加入；本人恢复必须匹配原快照，已有新状态或目标被删除时不应用旧日志。
4. 读取/写入暂时失败可重试；未知或损坏的主索引/日志原样保留，不按空库覆盖。已保存的本人恢复副本优先本地重试，不因一次校验失败重新联网下载。
5. 显式删除前把已有日志标为取消自动恢复，删除失败保留待处理线索；重启不自动删文件，也不自动完成被取消的保存。成功删除再移除日志。

日志不输出音频、完整路径、用户标识、分享口令或指纹；继续使用固定阶段的脱敏诊断。

## 保证边界

- 能补救：实际路径日志已落盘、主索引失败或随后进程退出，且原音频仍可读取。
- 不能承诺：原生保存尚未回调或日志尚未写成功时进程被强杀；主索引和日志都写不了；清除微信数据、换机、磁盘损坏或文件本身已消失。
- 不用全目录扫描或相同时长猜测文件归属，不会把别条录音当作恢复源。
- 上次真实手机“更新后旧录音回听失败”的根因仍缺原设备脱敏日志；本修复不等于已证明该问题由保存中断引起。
- 不改变分享 30 天的访问期限；当前关闭物理清理，云文件不会因此自动释放。正式删除仍需单独验收和明确授权。

## 精简验证安排

自动化仅增加保存日志专项，覆盖重启找回、持续写失败、离线恢复、快照冲突、防删除复活、取消失败保护、未知日志、指纹不符、双写失败与临时 IO 重试；同时在既有真实文件往返测试中检查“读指纹之前已经记录路径”。最终执行一次逐文件限时全回归、应用类型检查和微信构建，不重复浏览器截图矩阵（无 UI 改动）。

人工只补一条跨版本主流程：旧版准备两条短录音（未分享、已分享）→ 不清缓存正常更新 → 普通退出并重进 → 断网回听两条 → 新录一条并重启回听 → 联网分享给另一账号播放。

优先使用原来出问题的 Android 手机；iPhone 和 iPad 各复用同一条流程。保存中断/索引损坏/容量故障由合成数据自动测试，不要求家长灌满手机或强杀正在保存的重要录音。

本轮只准备本地代码及构建；正常录音回听通过与真实跨版本兼容通过分开记录，未实际执行的真机流程不勾选。
