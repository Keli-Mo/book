# English Voice Chat Implementation Plan

> 执行方式由用户选择；Git 分支、工作树、提交和推送均须先取得用户对具体操作的同意。每项完成后保留未提交改动。

**Goal:** 在微信小程序中提供可切换模式与难度的英语语音聊天、双语字幕、适度纠正和回复跟读。

**Architecture:** 新聊天页与现有教材跟读页分开。客户端负责录音、临时音频、播放、字幕和会话状态；新的云函数接收短音频，调用语音识别、对话模型及语音合成服务，返回文本与英文音频。服务端持有密钥，不保存聊天录音或聊天记录。

**Tech Stack:** Taro 4.0.12、React 18、TypeScript、微信小程序 RecorderManager / InnerAudioContext、微信云函数。首轮试用选择腾讯云一句话识别、DeepSeek `deepseek-flash` 文本对话和腾讯云精品英文语音合成。

**当前状态（2026-11-11）：** 本地源码、专项检查和小程序构建完成。云端密钥尚未配置，也未部署或进行真机调用。试用配置见 [英语语音伙伴试用配置](../../voice-chat-trial-setup.md)。

## Global Constraints

- 语音只朗读英语；屏幕同时显示英文与中文。
- 两档难度：基础、进阶；两种模式：自由聊天、主题聊天。
- 轮流说话；孩子主动结束录音后才提交。每轮最多纠正一个重点。
- 聊天和现有跟读录音的数据路径分开；不把聊天录音写入“我的打卡”。
- 不修改现有教材练习的保存与分享语义。
- 首版聊天记录只在当前打开的页面内存中存在；退出清除。

## File Map

- `src/features/voiceChat/session.ts`：请求、响应、模式、难度、消息类型和会话状态。
- `src/features/voiceChat/session.ts`：两模式隔离、主题重开、迟到结果屏蔽。
- `src/features/voiceChat/recording.ts`：借用全局录音协调器管理聊天录音及临时文件。
- `src/features/voiceChat/playback.ts`：英文回复播放与重听。
- `src/services/voiceChat.ts`：云函数调用与响应校验。
- `src/pages/VoiceChat/VoiceChat.tsx`、`.scss`、`.config.ts`：选择模式、难度、聊天、双语字幕和跟读操作。
- `src/pages/Home/Home.tsx`、`.scss`、`src/app.config.ts`：添加入口与页面注册。
- `cloudfunctions/voiceChat/index.js`、`handler.js`、`providers.js`、`package.json`：音频识别、对话、翻译与英语语音合成。
- `scripts/test-voice-chat-*.cjs`：状态、协议及服务端行为检查。

## Task 1: 验证云端语音链路与协议

- [ ] 查腾讯云和 DeepSeek 官方文档并用测试环境验证：微信录制的 MP3、英文一句话识别、英文音色、DeepSeek JSON 返回结构、云函数请求和响应大小。单轮录音上限先定为 30 秒；如果传输限制不允许直接提交音频，改为云托管短时请求，不使用永久云存储中转。
- [ ] 定义 `VoiceChatRequest`：`{ requestId, mode, level, topic?, turns, audioBase64 }`；`VoiceChatResponse`：`{ requestId, transcript, replyEn, replyZh, correction?, audioBase64 }`。`turns` 只含当前模式已确认的文本，不含音频。
- [ ] 验证中文译文和纠正内容与英文回复一致；语音只合成 `replyEn`。测试一轮真实英语输入并记录耗时、响应体大小、服务方数据留存条款。
- [ ] 确定单轮和每日调用上限、超时、输出字数限制；凭据只从云函数环境读取。缺少凭据时返回明确配置错误，不在客户端提供假成功回复。

## Task 2: 客户端会话状态

- [ ] 为 `session.ts` 写测试：模式各有独立记录；切回原模式继续；新主题清空该主题的旧记录；调整难度不清空记录；旧 `requestId` 的响应被丢弃；失败不加入上下文。
- [ ] 实现单轮状态 `idle → recording → processing → speaking → idle`，另有 `error`；聊天输入和跟读录音不得同时占用 RecorderManager。
- [ ] 运行 `node scripts/test-voice-chat-session.cjs`，确认上述转移与过期响应检查通过。

## Task 3: 录音、网络和播放

- [ ] 用现有 `getRecorderCoordinator()` 获取唯一录音所有者；权限拒绝、页面隐藏、停止超时和迟到回调沿用协调器保护。聊天录音仅保留临时路径，提交结束后清理；跟读录音只用于本地回听。
- [ ] `src/services/voiceChat.ts` 校验请求和响应字段、文本长度、音频大小及 `requestId`，通过 `wx.cloud.callFunction` 调用新函数；错误分为权限、网络、识别失败、服务超时和播放失败。
- [ ] 英文回复音频落到临时文件后播放；页面离开或新一轮开始时停止并清理。验证录音、网络请求与播放三者中只有预期的一项处于活动状态。
- [ ] 运行录音协调器和新聊天网络/播放检查；再跑 `yarn build:weapp`。

## Task 4: 云函数

- [ ] 校验身份、音频格式与大小、模式/难度/主题、上下文长度；拒绝空白、过长或非法输入，限制每轮最多 30 秒录音。
- [ ] 英文识别低置信或空结果返回“请重说”，不生成聊天回复。模型提示分别约束两档难度、两种模式、每轮最多一处纠正、儿童适宜内容和结构化输出。
- [ ] 对模型输出做服务端结构校验；只把英文回复送语音合成。任何一环失败都返回可重试错误，不把半成品写入会话。
- [ ] 增加无凭据、非法输入、识别失败、模型无效输出、合成失败、正常回复的云函数检查。日志不记录原始音频、完整转写或完整聊天内容。

## Task 5: 页面与入口

- [ ] 在首页添加清晰的“英语聊天”入口并注册独立页面。首次进入显示语音会发送至服务端处理的说明及麦克风授权说明。
- [ ] 页面提供模式和难度选择；主题模式先提供有限的通用主题；聊天过程中可切换。英文与中文逐条显示，语音只读英文。
- [ ] AI 消息提供重听、跟读、回听；纠正卡片显示英文示范及简短中文说明。识别不确定时提供重说或修正转写入口。
- [ ] 手机和 Pad 真机核对麦克风授权、后台切换、耳机/扬声器播放、网络中断、返回页面和连续多轮聊天。

## Task 6: 隐私与验收

- [ ] 更新小程序隐私说明：聊天音频何时上传、服务商处理、页面退出后清除、与原教材跟读录音的区别。核对所选服务的留存规则后再发布。
- [ ] 运行新专项检查、现有录音相关测试和 `yarn build:weapp`。人工检查自由/主题上下文隔离、两档语速与回复长度、英中字幕一致、纠正后追问、跟读不会变成新消息。
- [ ] 未配置服务凭据或未完成微信真机与隐私验收时，不把页面作为已上线功能开放。
