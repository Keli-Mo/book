# 录音升级保留、云副本恢复与一次性测试重置

日期：2026-09-19

状态：用户已同意保留与恢复方案，并明确要求“做清除前先跟我再确认再执行，先修复”。当前仅实施第 4–6 节修复及对应验证；第 7–9 节为后续候选方案，不在本轮实现、部署或启用。尚未执行任何删除。

## 1. 目标与已确认范围

用户确认现有录音全部属于可删除的测试数据，包括用户自己的录音。采用先修复、验证，再一次性重置测试数据的顺序。重置不能替代故障定位或升级验收。

最新执行约束：现有数据可删除的范围确认，不等于立即执行许可。任何云端或本地测试数据清除之前，必须再向用户展示具体范围与数量，并取得新的明确确认；不得通过发布新版自动越过此门槛。

本次目标：

1. 正常版本更新不主动删除本机录音、丢弃旧索引或将读取异常当成空库。
2. 本机回听失败时保留记录，提供准确的后台诊断；关联了可用本人云副本的录音允许主动恢复到本机。
3. 验证完成后，对已圈定的旧测试录音执行一次性云端及逐设备本地重置。
4. 重置后新录音不进入旧清理清单；后续普通版本更新不重复重置。

不在范围内：教材、封面、示范音频、学习进度、设置、全部录音自动云备份、付费套餐调整、全桶权限调整、生产过期清理定时器启用、分享按钮交互重做。

工作区为 `.worktrees/all-books-device-recording`，分支 `codex/practice-home-navigation`。既有用户修改的三个配置文件不纳入本设计提交，也不擅自覆盖。

## 2. 故障证据与结论边界

用户报告旧录音在更新后普遍提示播放失败；同一受影响手机新录音可以回听；原分享卡片里的同一旧录音能播放出声音。

已确认的代码事实：

- `recordingLibraryView.ts` 优先选择本机记录，按分享 ID 隐藏对应云端记录。
- `CheckInDetail.tsx` 的本机入口直接播放存储路径；原分享入口向云端刷新播放地址。
- 本机播放器报错后没有云副本恢复入口，页面也没有记录原生错误码。
- 原生文件访问明确返回不存在时，`pendingCheckInStore.ts` 会自动移除索引。
- 无法通过当前字段校验的旧索引项被过滤；后续持久化可能覆盖掉这些原始项。
- 与 9 月 12 日代码相比，存储键 `pending-check-ins-v1`、`saveFile` 保存方式未改变；未发现启动时清空所有录音的逻辑。

已通过现有页面测试适配器注入本地文件错误，验证“本机入口失败、无云回退、分享入口使用云地址”的分歧。此测试不证明真实手机的文件丢失原因；不能将推测写为已确认的升级路径故障。

删除故障样本前，需要在受影响设备上取得脱敏错误及文件访问结果，区分文件不存在、不可读、内容变化、格式或播放器兼容性问题。不能以清空后新录音正常作为修复证据。

## 3. 方案选择

采用“本地保留保护 + 用户主动恢复已有云副本 + 独立的一次性测试重置”。

曾考虑的替代方案：

- 仅从云端临时播放：改动较少，但没有恢复本机离线回听能力。
- 所有录音自动云备份：有更强的跨设备恢复能力，但改变只在主动分享时上传的政策与成本，不采用。
- 直接清空所有数据：不能验证旧数据兼容问题，不采用为修复手段。

## 4. 正常升级的数据保护

继续使用固定的本机录音存储入口，不将 app 版本号作为录音目录、存储键或删除条件。不为了本次修复搬迁全部有效音频。

索引读取、兼容和写入规则：

1. 读取失败不等于空库，阻止覆盖原索引并允许重试。
2. 对仓库历史代码可证实的旧格式进行确定性的兼容转换；不得凭书名、时长或文件名猜测录音身份。
3. 无法解释的旧项保留原始信息并报告诊断，不在下次写入时静默丢弃。
4. 首次兼容迁移写入前保存一份本机原始索引快照；备份失败则不覆盖旧数据。备份是元数据保护，不是音频备份，也不上传云端。
5. 恢复快照时必须遵守已完成的删除/重置标记，不能让用户已删除的录音重新出现在列表中。
6. 路径不可读或不存在时保留索引，标记不可用状态；本机列表仍能说明该录音的情况。
7. 普通保存、分享成功、云端过期和容量检查均不得自动淘汰旧本机录音。明确的用户删除和本次已授权重置是独立操作。

保存成功继续以 `saveFile` 返回的真实路径和实际文件信息为准，不保存原临时路径作为跨会话路径。失败必须显示未安全保存，不能虚报完成。

## 5. 诊断与最小界面变化

诊断覆盖列表来源、存储读取、路径访问、文件信息、播放启动、原生播放报错、云恢复和重置阶段。

仅记录固定阶段名、构建/平台版本、来源类别、错误码及脱敏分类、字节数与校验是否匹配等必要信息。禁止输出完整路径、云文件 ID、OPENID、分享口令、签名 URL 或音频内容。记录短关联编号用于串联同一次操作，不建立远程录音采集功能。

正常界面不新增复杂管理流程。本机失败时显示易懂提示；只有存在已关联分享的恢复候选时才出现“从分享恢复”。未分享、分享失效或无权恢复时给出明确原因，不暗示必然可以找回。

## 6. 恢复已有本人云副本

恢复由用户点击触发；进入页面和播放失败本身不启动下载，更不启动上传。

顺序：

1. 保存当前本机记录编号、修订状态与分享 ID，阻止同一条并发恢复。
2. 云函数通过可信微信上下文核对记录所有者，检查未删除、有效期及文件引用；服务端不能信任客户端传来的 owner 标记。
3. 持有分享口令仍可按既有规则收听，但不足以通过“恢复本人录音”的管理接口。身份判断自动完成，不增加实名、登录或手填口令界面。
4. 服务端返回受限的恢复信息。只针对精确分享 ID；禁止按教材、时间、时长搜索一个类似文件替代。
5. 检查本机空间后下载，限制单文件不超过现行 8 MiB；继续遵守应用设置的 100 MiB 管理预算与 10 MiB 安全余量，不将其表述为所有机型统一的系统上限。下载必须有超时、取消和实际大小校验。
6. 对已有大小和内容指纹的记录核对完整性。有证据矛盾时停止恢复；无旧指纹时，以通过所有权与引用验证的精确云记录为来源，建立新指纹，不能声称已与不存在的旧基准比对成功。
7. 将下载文件持久保存，确认真实保存路径与文件信息，最后原子更新同一条本机记录的路径。不得新增重复录音，不改变练习上下文、原分享期限或分享 ID。
8. 保存前后再次校验记录未被删除、重录或重置。迟到响应不得复活旧记录；失败时保留原引用，管理好本次新产生的文件，支持重试而不无限复制文件。
9. 保存成功后恢复正常本机回听，关闭页面或重启后仍使用已保存的本地路径。

恢复不调用分享 prepare/upload/commit，不续期，不绕过过期规则。只能恢复仍存在且允许本人读取的云副本；不承诺找回从未上传且已丢失的音频。云端下载会使用流量，不新增上传副本。

## 7. 一次性测试重置的公共边界

使用独立、固定的测试重置批次标识；它与普通 app 版本号无关，也不是管理接口凭证。生产默认不执行删除。

先预演并冻结清理清单，再删除清单里的对象；禁止每次重试重新执行“所有当前录音”查询。记录批次、环境、截止点、候选数、文件数、字节数及失败项，不将敏感原始清单提交 Git 或打印普通日志。

保留最小删除标记以防迟到上传和旧备份复活。用户侧从零开始不等于物理删除所有数据库防重放状态。

云端清空不意味着离线设备已清空。本地只能在相应设备执行新版时处理；不能对尚未更新的设备报告完成。

## 8. 云端测试录音清理

目标环境沿用 `cloud1-6geu18jg425a604e`，执行前重新核对实际连接环境与对象边界。

清理对象包括批次冻结前的已确认测试录音记录及其音频，覆盖旧 `checkins/` 与新 `expiring-shares-v2/` 录音协议。不能直接复用仅面向新版过期分享的自动清理条件，也不能清空整个存储桶。

管理执行必须满足：

- 普通小程序用户和分享链接不能触发批量清空。走受信管理入口，默认只读预演。
- 枚举所有分页；不使用用户界面最多 50 条的列表作为全部数据清单。
- 核对真实存储前缀、文件归属与全部引用；路径无法确认或有范围外引用时跳过并报告。
- 孤儿文件仅在能够证明属于两类录音目录、且在冻结清单内时纳入；不能按整个桶或含糊的 `.mp3` 后缀删除。
- 切换时阻止旧客户端继续准备和确认旧协议分享：服务端使用明确的录音写入代次要求，新版写入携带新代次；旧端得到更新提示。代次不替代身份鉴权。
- 先阻止旧写入并等待在途操作收口，再冻结旧记录与对象清单；预演阶段不改变线上写入策略。
- 对目标先写删除中状态以拒绝新读取和复活，再删文件，验证结果后写完成状态。明确文件不存在可收敛为成功；权限、网络或不明错误不能当作成功。
- 中断后只继续原批次未完成目标；不扩展到切换后新代次生成的录音。
- 删除必要状态保留，不通过清空整个集合使历史请求重新可用。

本批次不打开 `SHARE_CLEANUP_ENABLED`，不创建周期性删除触发器，不改变正式 30 天过期清理的独立验收要求。

旧分享将被服务端判定失效；已签发 URL、缓存及用户主动下载的副本不保证同步即时消失。云音频删除不可依靠 Git 回滚恢复。

## 9. 每台设备的本地一次性重置

仅在发布配置显式启用此固定批次时，新版第一次初始化录音仓储才执行重置门闩；诊断版和恢复验收版保持关闭，不能一进入就删除故障样本。启用后在接受新录音、恢复和分享操作前执行批次门闩，不依赖手机时钟判断新旧。

1. 先读取并冻结本机旧记录 ID 与准确文件路径清单，持久化清理进度后才开始删除。
2. 只处理本应用能够证实归属于旧录音的文件和索引。不调用 `clearStorage`，不递归清空用户文件目录，不删除教材缓存或学习进度。
3. 读取失败、未知索引格式或未能确认归属时停留在可重试状态，报告未完成范围；不能将空读取写为全部完成。
4. 清理与仓储保存、分享、恢复串行；不可取消的在途操作必须安全收口后再处理，不边录边删。
5. 每删除一个目标都确认成功或明确不存在，再更新批次进度。错误不能直接抹去最后一个路径引用。
6. 本地完成标记与新录音代次独立保存；重启继续原清单。完成后不再次扫描删除新录音。
7. 重置后的记录显式带新录音代次。即使单个批次完成标记损坏，也不能把新代次记录重新当成旧数据删除。
8. 为防旧索引快照复活测试记录，重置完成后仅保留最小批次/删除状态；包含已删测试数据的旧快照不得参与正常恢复。
9. 全新安装没有旧记录时直接记录该批次已处理。晚更新设备只处理该设备的旧代次；已完成重置的新代次录音始终保留。

只有本机验证成功才显示一次简短完成提示。失败时说明未完成并允许重试；不得让用户误以为当前所有设备都已清空。普通未来版本不得更换批次标识重新触发清理。

## 10. 验证与发布门槛

自动化必须覆盖：

- 历史格式载入、读取失败、未知项保留、索引备份写失败、缺失文件保留。
- 本机可播不联网；本机失败不静默下载；精确云记录恢复后离线回听且不新增上传。
- 非本人恢复拒绝，但原分享收听不被破坏；过期、删除、串号、内容不符均拒绝恢复。
- 恢复下载中断、超限、空间不足、保存成功但索引失败、离页、删除/重录/重置竞争及重启恢复。
- 云批次分页、去重、跨范围引用、错误前缀、失败重试、在途旧写入、旧客户端拒绝、新代次保护。
- 本地批次断电/退出后继续、离线、晚更新、部分失败、完成标记丢失、未知文件跳过、后续多次升级不再删除。
- 无原始路径、OPENID、口令、URL 或 SDK 任意错误内容泄漏至日志。

真机验收：

1. 先在受影响设备取得旧录音失败诊断与文件信息，不删除或覆盖原样本。
2. 旧版录音 → 普通退出 → 安装修复版 → 重启 → 本机回听，记录是否需要恢复及具体原因。
3. 本机失败 → 主动云恢复 → 关闭页面 → 断网 → 重启后回听。
4. 用专用测试数据验证一次性清理 → 新录音 → 再更新/重启多次，新录音不消失。
5. Android、iOS 及 Pad 的录音/回听、横竖屏与故障提示至少分别验收；不把模拟播放器的测试通过当成原生解码通过。

若原始失效原因尚未定位，可以报告恢复能力已通过，但不得标记升级丢失根因已经修复。真机条件未满足时，不宣称可放心正式发布。

## 11. 实施和回滚顺序

1. 按用户“先修复”的要求，当前仅为保留保护、诊断和主动恢复形成实施计划及失败测试。
2. 完成诊断、保留保护与主动恢复；旧数据仍在的条件下完成故障定位与升级回归。
3. 修复验收后再另行准备重置逻辑与隔离测试；本轮不实现重置。云管理入口只读预演。
4. 部署支持新代次的服务端代码但不立即启用重置；准备新版客户端和发布说明。
5. 在实际清理窗口先展示范围与数量、再次取得用户明确确认；之后才允许阻止旧写入、等待在途操作、冻结并核验清单，执行一次性云清理并启用客户端本地批次。
6. 逐设备确认本地完成；单独核验新录音重启和再升级后的保留。报告云端与本地各自的完成状态。

发生异常停止接收新的清理目标，保留批次清单和进度；允许修正逻辑继续，禁止回滚到旧端自动删除/旧协议可复活的行为。任何“全部清理完成”声明必须基于核验结果，不能仅凭 HTTP 200 或空列表。

## 12. 保证范围

验收目标是应用正常更新不会主动丢弃录音，并可诊断、处理已知故障。不能承诺微信数据被用户清除、卸载、换机、存储介质损坏或不可控平台行为后，本地音频永不丢失。

本方案维持仅主动分享时上传。未分享录音没有云备份，已过期或已删除的云副本不能恢复。测试重置后的旧音频不提供撤销承诺。
