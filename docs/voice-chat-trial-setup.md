# 英语语音伙伴试用配置

默认正式服务使用腾讯云一句话英文识别、DeepSeek `deepseek-flash` 和腾讯云精品英文语音合成。当前开发版和体验版直接调用独立测试函数 `voiceChatDiagnostics`，使用 DeepSeek 语音识别及最新混说规则；正式版及未知运行环境继续调用 `voiceChat`。正式云函数保持原代码和配置。小程序端只在开发版和体验版首页显示语音入口。

## 当前体验分发方式（2026-11-24）

测试服务已按用户要求开放，无需逐个提供 OpenID 或维护云函数白名单。前端录音、重新回答、重新发声、额度及身份查询统一按微信运行环境选择函数：`develop` / `trial` 使用 `voiceChatDiagnostics`，`release` / 未知值使用 `voiceChat`。真机不依赖本机托盘助手，介绍页控制逻辑未改。

原来三个本人名单继续保留，仅其交集可以产生有限的失败原文诊断；普通测试用户不会因服务开放而记录聊天正文。ASR、语音合成、超时、凭据和其他环境变量维持原值。

## 错误归属与语言引导（2026-11-24）

纯中文且意思明确时，模型先回应意思、给出一句短英语示范，再温和邀请复述；中英混说继续正常交流，最多补一个有用表达。已有识别文字但意思不明确时，模型用英文请用户用一句简短英语再说一次，同时配中文字幕。粗口只温和引导友善表达，不复述粗口或推断情绪。英文发声字段不得引用中文原句。

完全没有识别文字（`NO_SPEECH`）仍是录音失败，提示靠近麦克风、慢一点说一句简短英语，不生成虚构用户气泡，也不额外调用模型或合成引导语音。ASR 超时、授权及服务异常保持各自原因，不假称没听清。模型字段类型、长度、英文语言限制等失败也有独立固定文案，避免归因于用户说中文或发音不好。截图没有关联请求编号与原录音时，不能仅凭粗口转写或日志时间判定识别错误/客户端版本。

## 聊天音频缓存

每个聊天模式最多保留最近可重听的 10 段音频，同时限制解码后总量不超过 1 MiB；自由聊天与主题聊天合计最多 20 段 / 2 MiB（内存 Base64 约 2.67 MiB）。新回复优先保留，较旧的音频释放后不再显示重听按钮；字幕及供模型使用的最近 8 轮上下文保留，不限制对话次数。此上限针对聊天合成音频，不删除跟读、其他模块或待上传录音。

切换主题时先停止播放并删除离开的主题音频，退出页面时清理保留文件；启动扫描只删除当前用户目录下标准命名的遗留聊天音频。保存去重，迟到保存会清理，等待旧文件删除完成后才允许新的重听保存，防止误删新文件或静默无声。本机开发者工具的容量统计缺陷仍属于工具本身，未把模拟器恢复脚本打包到小程序。

2026-11-17，单人试用的 `voiceChat` 云函数已配置 30 秒超时。用已授权的测试账号发送一句英文录音，约 4.7 秒收到识别文本、双语回复和英文音频。用户已确认手机能播放试听音频。

同日新增独立的计轮预览函数 `voiceChatQuotaTrial` 和账本 `voice_chat_quota_trial`，共用现有云开发环境。真实数据库已验证五轮耗尽、最后一轮并发、重复确认和第六轮拦截。开发者工具中一次真实语音请求经页面播放确认后从 5 轮变为 4 轮，重复确认保持 4 轮。

根据用户的测试要求，当前本人微信账号在两个试用函数中均已设置为不限轮。`quotaStatus` 实测返回 `kind: "unlimited"`。该账号的对话绕过额度预留与扣轮，可连续测试。家长体验的 5 轮规则保留给后续获邀体验账号。

修复首次录音时的说明弹窗按钮长度，将五个汉字改为四个汉字「同意继续」。原生预览和源码均已同步，回归测试校验微信弹窗按钮的四字限制。

## 失败诊断日志增强（独立诊断函数已启用）

2026-11-19 已部署独立函数 `voiceChatDiagnostics`，仅用于本机模拟器诊断；原 `voiceChat` 函数保持原代码和配置。诊断函数的允许、内部不限轮及原文诊断名单均仅含当前本人测试账号，`VOICE_CHAT_QUOTA_ENABLED=false`，不访问额度账本。其代码来自本分支的 `cloudfunctions/voiceChat`，下载云端文件逐项核对 SHA-256 一致。

本机项目外的 `E:\tools\wechat-practice-tray` 通过配置 `voiceDiagnosticFunction: "voiceChatDiagnostics"`，仅在指定 AppID 的 develop + devtools 运行时把原 `voiceChat` 请求转到诊断函数；包含额度查询及音频转换后的调用。客户端源码和 dist 均未为此改动，真机、体验版、正式版及其他云函数保持原调用。关闭助手的本地豁免，或移除该配置后重新启用，即恢复原路由。

继续使用云函数现有日志，每次失败只写一条 `voice_chat_failure`。新增信息留在服务端，不改变客户端错误协议、提示词、模型参数、重试次数或计轮规则。成功的请求不写新增的失败诊断日志。

- `requestId` 串联一次请求；`mode`、`topic`、`level`、`historyTurns` 描述场景。
- `elapsedMs`、`stageMs`、录音字节数/时长、转写字符数用于定位耗时及输入规模，不包含录音。
- `model.finishReason`、`contentKind`、原文/去空白字符数、`blank`、输入/输出 token 数描述模型返回。固定枚举和数值过滤防止把上游任意文本带入默认日志。
- `reasonCode` 定位以下具体失败，字段校验还记录 `field`，超长时记录 `actualLength` 与 `maxLength`。

| reasonCode | 原因 |
| --- | --- |
| `MODEL_CONTENT_EMPTY` | 模型内容为空或全空白；`contentKind` 区分 empty 与 whitespace |
| `MODEL_CONTENT_MISSING` | 模型内容不存在或类型不是字符串 |
| `MODEL_FINISH_INCOMPLETE` | 结束原因不是 stop；例如 length 表示达到生成上限 |
| `MODEL_JSON_INVALID` / `MODEL_OBJECT_INVALID` | 回答不是有效 JSON / 不是有效对象 |
| `MODEL_FIELD_TYPE` / `MODEL_FIELD_EMPTY` / `MODEL_FIELD_TOO_LONG` | 某字段类型不符、为空或超长 |
| `MODEL_ENGLISH_INVALID` / `MODEL_CHINESE_MISSING` | 英文含非拉丁文字或不含英文字母 / 中文翻译缺少汉字 |
| `MODEL_CORRECTION_MISMATCH` | 纠正示范未逐字出现在英文回复中 |
| `MODEL_HTTP_JSON_INVALID` / `MODEL_HTTP_RESPONSE_TOO_LARGE` | HTTP 返回不是 JSON / 超出大小限制 |

例如此次纯空格响应将留下 `reasonCode: MODEL_CONTENT_EMPTY`、`model.contentKind: whitespace`、`model.finishReason: stop`、`model.trimmedCharacters: 0`，无需取得原文即可知道直接失败原因。

需要核对“当时识别成了什么”时，可在部署日志增强的测试函数中配置 `VOICE_CHAT_DEBUG_OPENIDS`，只填写参与排错的内部账号。账号必须同时位于 `VOICE_CHAT_ALLOWED_OPENIDS`、`VOICE_CHAT_UNLIMITED_OPENIDS` 和此诊断名单，三者缺一均不记录原文；微信 SDK 返回的真实 OpenID 是判断依据，客户端传入的 debug/openId 不生效。默认诊断名单为空。

对这些账号的失败请求，额外写 `debugText.transcript`（最多 500 字符）与 `debugText.modelContent`（最多 2000 字符），并标明是否截断。常见 API key / Bearer 样式会遮盖；不记录音频、请求头、环境变量、完整请求、原始异常或整段聊天历史。诊断文本用于测试，测试结束后移除诊断名单即可停止新增原文日志；已有记录按云平台日志保留设置处理。

按 `requestId` 或具体 `reasonCode` 查询云函数日志，例如：

```powershell
tcb logs search -e cloud1-6geu18jg425a604e --query 'function_name:"voiceChatDiagnostics" AND log:"MODEL_CONTENT_EMPTY"' --timeRange 30m --limit 20 --json
```

部署时只更新已确认的测试函数，并保留其现有环境变量、权限、超时及额度配置；不需要重新打包小程序。日志写入异常会被忽略，不改变回答结果，也不阻止失败请求释放额度预留。

本次现场验收：正常 MP3 与模拟器 WebM 样本完成识别、英文回复和合成音频；带三轮历史的失败样本在诊断函数写出 `MODEL_CONTENT_EMPTY`、`contentKind: whitespace`、86 个原始字符、去空白后 0 字符及有限文本。原函数查询该请求编号无记录，部署前后原函数代码与配置指纹一致。回答格式异常本身尚未修复，本次仅增加可定位问题的日志。

## 用户可见的错误原因

尚未取得识别文字时，页面在气泡上方显示简短原因和下一步，不显示原始异常或日志。已知错误分别提示麦克风权限、未识别到文字、网络连接、服务繁忙、语音生成失败。识别失败但没有可靠细节时明确提示“原因暂未确认”，不推断用户没有说清楚。

任务分支新增分段恢复（2026-11-24，已仅部署至测试云函数 voiceChatDiagnostics）：客户端发送 `progressProtocol: 1`，识别后回答失败返回已验证的 `partial.transcript`；发声失败还返回已验证的英文、中文和可选纠正。页面保留用户气泡，将错误和「重新回答」/「重新发声」放到对应回复中。前者跳过识别，后者跳过识别和模型，只重试语音合成。重试沿用原请求编号与原上下文，更新同一条消息；未取得回答的占位消息不进入后续模型上下文。重试仍需服务端身份、白名单、输入和额度检查，失败释放预留，成功首次播放后才确认一次扣轮。部分结果只留在当前页面内存，不额外写入数据库或开启正文日志。旧客户端不收到部分结果；连接超时等没有收到服务端结果的情况，不能凭空恢复首次识别文字。

第一轮恢复改动增加了两个有效 JSON 示例，保留格式校验与分段恢复。三句固定英文的新旧提示共六次真实接口调用均返回有效结果，但随后带多轮历史的实际录音再次得到纯空格响应，因此不能只靠增加示例判断问题已解决。页面分段恢复通过模拟空回复、合成失败、重复点击、重试失败及离开页面的测试验证。2026-11-24 经用户授权，先仅更新测试云函数 `voiceChatDiagnostics`，验证录音识别、重新回答和重新发声均成功。后续针对空回答和识别的进一步改动及验收见下一节；未上传小程序或发布线上版本。

模型错误在原有 `BAD_MODEL_REPLY` 上增加白名单 `reasonCode`，客户端可区分 AI 没有返回回答、未生成完整回答、内容无法读取和缺少中文字幕；旧函数未返回原因或未知原因时使用通用提示。重复经过前端错误处理仍保留安全原因，不返回诊断原文、音频、供应商消息或凭据。

识别适配器检查实际录音头，遇到 EBML/WebM 时返回 `AUDIO_FORMAT_UNSUPPORTED`，不向只接收 MP3 的识别接口发起收费请求。手机提示录音格式不兼容；开发者工具单独提示启用本地语音助手。助手、转码和入口豁免代码仍放在项目外，小程序只包含错误展示。

## 英文识别对照与空回答恢复（2026-11-24，仅测试函数）

对同一条约 6 秒的测试录音，原 WebM 与转码 MP3 对齐后的波形相关系数为 0.99914，尾部 600 毫秒为 0.99669，未发现尾部音频被截掉。此证据只适用于已保存的这条录音，不能推断没有原录音的其他失败。

| 方案 | 这条录音末句的实际结果 |
| --- | --- |
| 腾讯 `16k_en`，当前 MP3 | `I like pasqui I Ming.` |
| 腾讯 `16k_en`，原录音解码为 WAV | `I like pasquati, I Ming.` |
| 本地 Whisper `small.en` | 原录音为 `I like past gate Yimian.`；MP3 为 `I like past-skatey immune.` |
| DeepSeek ASR | 原录音 WAV 为 `I like spaghetti面。`；实际服务端 MP3 解码路径为 `I like pasta t意面。` |

用户确认最后说的是意大利面。DeepSeek 在这条样本上抓住了关键内容，但仍有中英混杂与多余字符；保留原识别结果，不用模型改写冒充准确转写。这不是大样本准确率结论，也不能据此判断其他 Whisper 模型的效果。腾讯 `16k_en_large` 对照请求返回 `FailedOperation.UserHasNoAmount`，未开通额外付费项目。

测试函数环境变量 `VOICE_CHAT_ASR_PROVIDER=deepseek` 选择 [DeepSeek ASR](https://api-docs.deepseek.com/guides/asr/)，复用现有 `DEEPSEEK_API_KEY`。该接口不接受 MP3，本函数用固定版本 `mpg123-decoder@1.0.3` 将录音解码为单声道 16 位 PCM WAV，再通过 HTTPS multipart 上传；不裁掉尾部、不做 VAD 或添加文本提示。真实 Nodejs16.13 云端已验证能加载解码器。缺省或 `tencent` 仍走原腾讯接口，未知配置明确报错，不静默切换其他服务。语音合成仍由腾讯云完成。

[DeepSeek JSON 模式文档](https://api-docs.deepseek.com/guides/json_mode/)说明，非 JSON 输出可能被空格替代。带旧式普通英文历史的对照中，取消 JSON 过滤后两次都返回普通英文而非 JSON，支持历史输出形式干扰格式遵循的判断，但不能证明所有空回答都由它引起。现在把最近对话完整保留为一条用户消息中的结构化数据，明确当前要回答的句子；不再用普通英文 assistant 消息作为格式示例。

仅当模型返回空字符串或纯空白时自动补试一次，两次调用共用 20 秒模型阶段预算；剩余不足 1 秒不补试。第二次仍空则返回原有部分结果，页面保留识别文字，允许「重新回答」。授权、连接、非空格式错误不自动追加调用。可选纠正失败仍不能拖垮主回复。失败日志至多记录两次模型响应的安全元数据，不增加成功正文日志；自动补试可能增加一次模型接口费用，不重复识别、不重复扣轮。

验收：68 项回归测试通过，12 次真实模型调用均通过回复字段校验。下载核对测试云端全部 9 个源文件及依赖清单与本地一致，仅新增测试识别提供方配置，其余测试配置保持原值；正式 `voiceChat` 的代码与配置指纹保持一致。开发者工具现有页面和隔离路由下，同一条实际 MP3 完成识别、双语回复和音频生成，约 6.86 秒；「重新回答」「重新发声」也成功，额度仍为 `unlimited`。有限次数的成功不代表以后不会出现服务故障或空回答。

录音、对照报告、部署备份及本地 Whisper 模型在项目外 `E:\tools\wechat-practice-tray\diagnostics` 和 `E:\tools\english-asr-compare`，不进入小程序包。测试回退可仅把 `voiceChatDiagnostics` 的 `VOICE_CHAT_ASR_PROVIDER` 改回 `tencent`，或使用项目外保存的部署前代码包；不要改正式函数。

## 中英混说规则（2026-11-24，仅测试函数）

用户可以中英混说或用中文表达暂时不会的词。识别文字及历史原样传给模型，返回用户字幕时只去除首尾空白；不先翻译成英文，不把混说判为错误。模型用全英文接话并提供中文字幕，理解时保留否定和喜好。需要表达帮助时，每轮最多选择一个词、短语或语法点；中文说明应友好，不要求用户禁止说中文。近期已经示范过的表达不重复纠正，除非用户主动再问。

对于 `pasta t意面` 等疑似识别杂字，意思清楚就自然接话，不把杂字教成语法或发音错误，也不评价用户说得好坏。意思不确定时先用一个简短英文问题确认，不自行补出具体词、不列出猜测的候选含义；此时不附纠正卡片。原始识别内容继续按既有内部失败诊断规则保留，没有新增成功正文日志。

对照发现旧提示会在重复出现中文词时返回“不要说中文词”，也会把不明确的“那个”猜成面条或米饭。更新后 6 类真实模型用例通过，包括明确混说、否定喜好、识别杂字、不明确指代、已教过的表达和中文为主的输入。70 项回归测试通过；云端通过既有 `retryReply` 路径输入这 6 类识别文本，均保留原文、生成双语回复和英文音频，内部账号不限次数。此验收检查的是已识别文本到回答及发声的行为，不代表重新测量了 ASR 准确率。

本次仅修改回答规则并更新 `voiceChatDiagnostics`，9 个部署文件逐项校验，其中只有 `providers.js` 相对上次部署改变；测试函数全部配置及正式 `voiceChat` 的代码和配置指纹保持不变。开发者工具页面未切换，未重新打包或上传小程序。当前规则依赖模型遵循，真实使用中仍需观察不明确表达的处理效果。

1. 当前排错只部署 `cloudfunctions/voiceChat` 的代码到独立函数 **`voiceChatDiagnostics`**，选择“云端安装依赖”，入口为 `index.main`。未经用户另外授权，不更新正式 `voiceChat`，不上传小程序。以下原始 `voiceChat` 配置说明供后续正式配置参考，当前试验对应配置均放在隔离测试函数。不要把凭据写进仓库或小程序代码。
2. 在「云开发 → 云函数 → voiceChat → 函数配置 → 环境变量」中新增 `VOICE_CHAT_TENCENT_SECRET_ID`、`VOICE_CHAT_TENCENT_SECRET_KEY` 和 `DEEPSEEK_API_KEY`。可选的 `VOICE_CHAT_TENCENT_REGION` 默认 `ap-guangzhou`。保留其他已有变量。腾讯云语音密钥只需一句话识别和语音合成权限。云端使用上述名称，因为 CloudBase 保留了 `TENCENTCLOUD_` 前缀。[CloudBase 环境变量说明](https://docs.cloudbase.net/cloud-function/function-configuration/env)
3. 函数默认超时通常只有 3 秒，三段串行调用需要在函数配置里调高超时。先用 **30 秒**试跑，并核对真机调用是否能同步返回；如果实际服务耗时接近客户端等待上限，应缩短单段超时或改异步方案，不能仅把函数超时无限调大。
4. 先保持 `VOICE_CHAT_ENABLED` 不设置。在微信开发者工具的小程序控制台运行下面的命令，取得**当前微信用户自己的** OpenID；这条查询不调用付费服务。将获准试用的 OpenID 以英文逗号连接，配置到 `VOICE_CHAT_ALLOWED_OPENIDS`。未配置白名单时，即使开启总开关也不会调用语音或模型服务。

     .then(({ result }) => console.log(result.ok ? result.data.openId : result.code));

## 家长试用额度

建议每个获邀微信账号首次获得 5 轮免费对话。各难度、自由聊天和教材主题共用次数。拟试价 4.9 元，体验包到账起 7 天内共 50 轮。当前客户端没有收款入口。

启用计量前，在试用环境创建集合 `voice_chat_quota`，把客户端权限设为「所有用户不可读写」。部署匹配的云函数和小程序预览后，在函数的 `VOICE_CHAT_UNLIMITED_OPENIDS` 里填内部测试账号，同时保留这些账号在 `VOICE_CHAT_ALLOWED_OPENIDS` 中。把获邀家长加入允许名单，设置 `VOICE_CHAT_QUOTA_ENABLED=true`。未设置计量开关时仍按原来的单人试用方式运行。

每次新对话先暂留一轮，手机收到回复并首次开始播放英文音频后才确认扣轮。云端生成失败时释放预留。若手机断网，或用户在播放前退出，预留在请求开始后 120 秒到期。同一请求重复确认只扣一次。重听已有回复、本地跟读和回听自己的录音都不额外扣轮。账本仅保存额度、请求及确认所需的记录，不保存录音、字幕或回复内容。

体验包的服务端发放方法为 `grantPack(openId, orderId)`。它接收由商家后台核实的账号和订单号，同一订单只到账一次。支付和订单核验尚未接入。这套播放回执适用于受邀家庭试用。未收到播放回执的请求仍可能产生接口费用，公开销售时应另外设置按账号的调用上限。

## 真机验收

本地分支的纠正容错（2026-11-24）：主回复仍须通过英文、中文及长度校验；纠正卡片是可选信息。有效纠正未逐字出现在英文回复中时，保留独立卡片，记录 `voice_chat_correction_warning / separate_card`；纠正字段无效时仅省略卡片，记录 `omitted`。这两种情况不重试模型、不改变原回复/译文、不阻止语音合成。警告仅含请求编号及固定原因，不含录音、转写或模型正文。此变更已于 2026-11-24 仅部署至测试云函数 `voiceChatDiagnostics`；正式 `voiceChat` 未更新。

开发者工具漏词对照使用项目外 `E:\tools\wechat-practice-tray\recording-compare.cjs` 临时采集同一请求的原录音、转码音频及结果，限本机 develop/devtools 及四条测试录音，20 分钟自动撤销。采集脚本和录音不进入小程序包。只凭代码测试或音频时长不能断定漏词原因，必须比较原始音频、转码后的波形/回听和该请求的识别文本。

- 用开发版或体验版进入“英语语音伙伴”，同意说明并授予麦克风权限。说一句 2–5 秒的英语，验证转写、英文语音、英中字幕、回复时间和音频文件大小。
- 分别试自由聊天、四个主题与基础/进阶档；检查主题切换不带入上个主题、两档回复长度与语速不同、中文翻译对应英文、每轮至多一处纠正。
- 用“重听”“跟读”“回听自己”验证播放和本地录音；切换模式、后台切换、拒绝麦克风、断网时检查是否能恢复，旧请求不能写入新会话。
- 在云函数监控核对时长、错误、调用量和实际费用。代码不记录音频、转写或密钥到应用日志，但平台及服务商的数据留存须单独核验。

## 隐私与数据

默认聊天录音通过微信云函数发送给腾讯云识别；当前独立测试函数选用 DeepSeek ASR 时，录音改发 DeepSeek。识别文本和最近最多 8 轮英语上下文发送给 DeepSeek；英文回复发送给腾讯云合成语音。应用当前不把聊天录音或聊天记录写入“我的打卡”或云数据库。部署本分支诊断增强并配置内部诊断名单后，失败请求的有限文本会按上节规则写入云函数日志；默认关闭原文记录。页面卸载后清理应用生成的音频文件；微信临时录音由客户端尝试删除。腾讯云语音识别文档说明识别后的文本可能在其服务器保存 7 天；不能把“应用不保存”写成“服务商立即删除”。上线前应按最终选用的识别服务更新小程序隐私保护指引，核对实际服务条款和儿童使用场景。
