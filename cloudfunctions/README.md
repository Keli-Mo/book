# 微信云开发部署说明

当前小程序固定使用云环境 `cloud1-6geu18jg425a604e`。仓库只包含云函数源码，不会直接修改线上云环境。

2026-09-13 的实际检查状态见 [录音容量与清理验收](../docs/recording-capacity-cleanup-acceptance-2026-09-13.md)。下文为部署规范，不能据此推断线上版本、权限或定时清理已经启用。

## 首次部署

1. 用微信开发者工具打开项目，确认 AppID 为 `wxdb6824b2da985a21`。
2. 在“云开发”中选择环境 `cloud1-6geu18jg425a604e`。
3. 在云数据库中新建集合 `checkins`。
4. 为 `checkins` 添加组合索引：`_openid` 升序、`createdAt` 降序，供“我的打卡”按时间读取。
5. 将 `checkins` 的客户端权限设置为“所有用户不可读写”。小程序不直接访问数据库，新增、查询和删除均由 `checkIn` 云函数按 OPENID 鉴权。
6. 在开发者工具左侧找到 `cloudfunctions/checkIn`，右键选择“上传并部署：云端安装依赖”。
7. 在真机上完成“录音 → 回听 → 完成 → 分享”，验证完成仅保存在本机、点击分享才上传，并检查下述新版分享配置。

## 数据内容

`checkins` 每条记录保存：用户 OPENID、教材/训练位置、录音时长、云存储文件 ID、创建时间和单条分享口令。题目、答案以及教材示范音频都不会作为打卡内容提交。

用户删除云打卡时，云函数先核验文件引用。协议记录先使分享失效，再确认删除文件并保留不可复活的墓碑；无请求编号的旧 create 记录在确认文件删除成功后仍删除数据库文档，失败保留原记录以便重试。

## 旧创建入口与存量引用核验（本地源码修复，尚未部署）

旧 `create` 入口已停用：登录调用统一返回 `LEGACY_CREATE_DISABLED`，未登录仍先返回 `UNAUTHENTICATED`。旧客户端必须升级为绑定 owner、请求编号、内容摘要及服务端路径的 `prepare` / `commit` 后才能新增。已有旧记录仍支持本人查看、正确分享口令访问及本人删除，不自动迁移文件或补写归属。

`checkIn` 在详情签 URL、commit 下载校验文件、本人删除文件之前，分页读取相同 `recordingFileId` 的全部记录，不排除过期记录和墓碑。发现不同 owner（含缺失 owner）的引用时返回 `FILE_REFERENCE_CONFLICT`，停止文件操作；查询异常也失败关闭，删除前不写墓碑。仅对服务端协议的完整路径核对 owner 摘要，避免旧别名访问尚未 commit 的协议文件；普通平铺旧路径不含可验证的 owner，未发现重复引用也不能证明它的真实归属。

旧引用冲突须由管理员依据可信上传记录人工核验，本修复不会自动选定“真正 owner”或删除冲突文件、引用。本轮没有读取真实云库做存量审计，也没有部署或调用线上函数；线上存量风险与最终归属仍待核验。引用查询增加数据库读取成本；线上查询可用性和耗时需在发布验收时核查，查询失败不会降级放行。独立清理函数也按下文核验新版完整绑定和全部 fileID 引用，但仍未启用。

## 新版 30 天分享（源码已实现，线上状态需验收）

`prepare` / `commit` 请求携带 `shareVersion: 2`。prepare 在事务中预留 `pending` 记录，保存 `cloudPath`、`payloadDigest` 和 `pendingExpiresAtMs`（服务端当前时间加 24 小时）。首次 commit 验证实际文件后，在事务中激活并写入 `expiresAtMs`（服务端当前时间加 30 天），幂等重试不会续期。返回的 `expiresAtMs` 是毫秒数。预留到期返回 `SHARE_EXPIRED`，客户端必须在用户再次分享时生成新请求编号；已删除请求也不能复活。

listMine复用 `_openid` 升序 / `createdAt` 降序索引，每页100条，持续读取到50条有效记录或真正末页。永久墓碑和pending超过100条不会把旧云历史伪装成空列表。无需增加列表索引，但墓碑非常多时读取成本会上升，须监测函数耗时/额度；数据库失败会返回错误，不用固定扫描上限伪造“没有历史”。

新版分享文件只在 `expiring-shares-v2/` 前缀，旧 `checkins/` 录音及教材不迁移。旧 create 已拒绝新增；未携带新版协议的 prepare/commit 仍使用原绑定协议及 `checkins/` 路径，无新协议期限的数据不自动清理。数据库客户端仍必须禁止读写；不要用 TTL 删除预留或墓碑，TTL 不会删除存储文件，还会丢失孤儿定位信息。

## 独立清理函数的上线准备

本轮分享恢复逻辑另见下文“本机分享恢复”；部署 `checkIn` 不会启用独立清理函数。

`cleanupExpiredShares` 默认不删除：仓库 `config.json` 未配置定时器，环境变量 `SHARE_CLEANUP_ENABLED` 未设为精确的 `true` 时只 dry-run。2026-09-13 经用户确认已部署到上述环境，状态 `Active`，回读的三个源码文件哈希与本地一致；本次未添加线上触发器、未设置删除开关、未执行清理，也未变更套餐。真实运行变量、索引、存储权限及可信触发器预演仍待验收，详见本页顶部链接。

1. 创建 `shareCleanupState` 集合，客户端权限设为所有用户不可读写。正式清理的分页游标保存在 `v2` 文档。为 `checkins` 添加 `shareVersion` 升序、`_id` 升序组合索引；保留已有 owner/时间索引。
2. 从当前环境一次真实上传的 fileID 确认环境和 bucket，配置函数环境变量 `SHARE_STORAGE_FILE_ID_PREFIX=cloud://<当前环境ID>.<真实bucket>/`。不能根据环境名猜 bucket。代码严格校验当前 SDK ENV、完整前缀和每个新版路径；缺失或无效配置会返回 `STORAGE_PREFIX_REQUIRED` 并强制 dry-run，连数据库状态都不修改。即使已提交记录有 fileID，也不绕过此部署核验。
3. 部署时先保持 `SHARE_CLEANUP_ENABLED` 未设置，单独配置平台定时触发器。入口只接受 SDK `getWXContext().SOURCE === "wx_trigger"` 且没有 OPENID；客户端、开发工具、HTTP 和 `wx_client,scf` 调用链均被拒绝。`event.Type`、`event.SOURCE`、`event.enabled` 不能授权删除。须在测试环境实际核验定时来源；若平台返回不同来源，保持停用并调查，不能放开为“没有 OPENID 就允许”。
4. 首轮 dry-run 检查日志中的 `scanned`、`candidates`、`validated`、`failed`、`nextCursor` 与 `STORAGE_PREFIX_REQUIRED`。`candidates` 仅表示到期候选；`validated` 表示已核对非空 owner、规范 requestId / payloadDigest、owner 摘要组成的完整新版路径、可信 fileID 前缀及 `recordingFileId` 全部引用。引用查询不按 owner、期限、状态或旧协议过滤；除允许 pending / 删除中记录 / 墓碑只有可信路径外，结果只能为空或只有目标自身，否则失败关闭。预演也会报告绑定、路径、跨桶 fileID 或引用冲突，不能仅凭 `ok:true` 宣布验收通过；必须没有配置错误、`failed === 0` 且 `validated === candidates`。缺少可信前缀时 `validated` 为 0，不意味着没有待清理数据。dry-run 不写游标、不删除文件；审核后续页需由可信触发器携带上一页的 `cursor`，或通过测试环境构造多页数据验证正式游标。普通控制台模拟事件被拒绝是预期行为。`validated` 只证明应用当前读取到的绑定与引用预检通过，不证明存储实际 ACL 安全，也不能排除管理员在预检后并发修改数据库。
5. 在测试环境验证仅新版孤儿和过期文件会删除、未知删除错误留引用、再次运行可恢复，完成私有存储核验后，才由部署负责人显式设置 `SHARE_CLEANUP_ENABLED=true`。事件 `dryRun:true` 可以降级为只读，事件不能开启删除。不要未经核查就在生产启用。

正式执行每次最多扫描 50 条新版记录，用 `_id` 游标跨次推进，扫到末尾回绕。函数在授权后、首次云端 I/O 前开始计算 1,200ms 工作软预算；预算耗尽时只是不再启动新候选，并返回 `budgetExhausted: true`，它不是网络或单操作硬超时。`scanned` 仍是本次取得的页大小，`processed` 是实际检查完并可安全推进的连续前缀；`candidates`、`validated`、`deleted`、`failed` 只统计实际处理项，`nextCursor` 不会越过尚未处理的记录。dry-run 使用相同软预算和返回游标，但不读取或写入正式游标，也不删除文件。

每个已处理候选（包括可重试失败）结束后都用事务检查 revision 并保存连续前缀，避免平台硬超时使整页进度丢失；失败记录保留引用，在游标回绕后重试，不阻塞后续安全记录。未到期记录不逐条写检查点，只在页尾或预算退出时集中保存，减少无效写放大。候选检查点会增加数据库事务读写成本；并发执行发现 revision 已前进会立即中止，较慢执行者不会覆盖较新游标。只有处理完页内最后一条且页长小于 50 时才保存空游标；满页保留末条 ID，并在下一次读取到空页时回绕。

每条删除在写 `deletePending` 前先核验完整绑定和同 fileID 的全部引用，并在首个事务中重新读取记录、再次确认期限、完整绑定和扫描时目标；引用查询只取两条，因为数据库 `_id` 唯一，第二条已经足以证明冲突。只有文件删除成功或 SDK 明确 `-503003` / `STORAGE_FILE_NONEXIST` 后才写 `deleted`。查询异常、冲突、超时、权限、泛化 404 和未知返回保留引用或墓碑，下个完整扫描周期重试；日志 `failed > 0` 需告警排查。引用查询耗时计入同一软预算，核验后预算耗尽不会开始文件删除，也不会把未完成候选计为已处理。本地测试用虚拟时钟和注入的查询/事务/删除耗时验证软预算早于模拟硬预算退出，不代表线上延迟或平台 3 秒配置已经验收。上线前仍须核实 `shareVersion` / `_id` 组合索引、`recordingFileId` 等值查询、单次事务和存储删除实际耗时、函数硬超时及完整轮询吞吐；清理时间受完整轮询周期影响，不承诺第 30 天整点物理删除。

`checkIn` 与 `cleanupExpiredShares` 的失败响应和诊断日志只使用固定白名单分类；不记录 SDK 原始 Error、stack、message、errMsg、任意错误码、事件内容、文件 ID、OPENID、口令或 URL。客户端同样只展示固定错误分类。该约束只描述应用代码输出，不代表平台日志留存期限或访问权限已经完成治理；上线前仍须单独核验平台配置。

客户端直传后未 commit 的文件只留下预留 cloudPath，没有 fileID；可信前缀是定位这些孤儿的必要条件。清理永久保留新版墓碑的路径和原期限并重复扫描，因此删除后才完成的迟到上传也能再次清除。暂停定时器、遗漏配置或存储删除失败时不会保证物理删除。对于任意非协议路径上传，需另行审核存储上传规则/生命周期或存储触发器兜底；本函数不枚举整个 bucket，也不声称覆盖所有任意上传。不要直接对新版前缀设置“上传后 30 天删除”：有效期从 commit 开始，上传到 commit 的间隔可能导致提前删掉有效分享。

## 分享 URL 的实际安全边界

detail/list 按服务端期限拒绝或隐藏过期新版分享；过期 detail 不再请求文件 URL。有效期内 detail 通过 `fileList: [{ fileID, maxAge }]` 请求临时 URL，maxAge 取剩余秒数向下取整且最多 300 秒，不足一秒不再签发。已用锁定依赖实际安装核验 `wx-server-sdk 4.0.2` 包装器会原样传递对象 fileList，底层 Node SDK 会发送 `max_age`；单位依据 [CloudBase 官方存储文档](https://docs.cloudbase.net/api-reference/manager/node/storage) 的秒定义，接口见 [Node SDK 存储](https://docs.cloudbase.net/api-reference/server/node-sdk/storage)。这验证了参数支持，尚未做线上签名有效期实测。

上线必须检查新版录音路径是私有读取：只有 owner 可以按既定规则上传，客户端不能通过已知 fileID 直接获取他人文件，函数才可按口令签发。不能为了私有录音直接把教材公共读取规则一起关闭，需在目标环境验证路径规则和现有教材不冲突。如果存储或 CDN 仍公开返回永久 URL，maxAge 不会把公开文件变私有，30 天只控制应用入口；严格 URL 失效不能宣称已实现。须实测返回 URL 在签名到期后不能从源站/CDN匿名读取，并检查自定义域名和缓存策略。网络签名请求也存在时间误差。

已签出的 URL 在其自身有效期内可能继续工作，删除并不撤回浏览器/CDN缓存或朋友已下载的音频；服务端 30 天失效不删除用户本机录音，也不能撤回他人保存的副本。来源 SDK 实现参见 [微信官方仓库](https://github.com/wechat-miniprogram/wx-server-sdk)，定时来源的目标环境验证属于启用前必做项。

## 本机分享恢复（本地源码修复，尚未部署）

完成录音和本机回听仍不上传。重开正在准备分享的录音时，页面观察同一提交任务的完成结果，不另起上传。本人云记录删除失败后，`deletePending` 以“待删除 / 重试”保留在列表；即使分享已过期或同时存在本机副本也保留，但不能回听或分享。删除成功后旧刷新结果不能把卡片恢复回来。

本机已有链接增加“链接打不开？检查分享”：仅用户主动点击时调用 owner-only `shareStatus`，同时核对记录 owner、分享代次和文件引用，再下载核验文件。它不返回录音地址或原始 SDK 错误。确认删除、过期、明确不存在或录音内容不匹配后，只使对应旧分享代次失效，保留本机音频；下一次点击分享才生成新代并上传。网络、权限、未知结果或本机状态写入失败保留原引用，不自动重传。泛化 HTTP 404 不等于明确缺失，可能仍需要管理员排查。

主动核验会产生云函数、数据库及存储读取用量，且需要在目标环境验证耗时；它不是后台保活或自动备份。客户端与 `checkIn` 必须配套发布：只更新小程序而不更新云函数，核验入口会安全失败而不能恢复。

## 录音流式核验（本地实现，尚未部署验收）

commit 和 shareStatus 在原有 owner、请求/代次和全部引用分页预检之后，通过 `getTempFileURL({fileList:[{fileID,maxAge:600}]})` 签名，并使用 Node 内置 HTTPS 单次 GET 流式计算大小和 SHA-1。只接收 SDK 明确成功包中的 HTTPS 地址，不跟随重定向、不解压、不重试；只接受完整的 HTTP 200 原始字节。签名地址不返回、不落日志，错误只使用固定类别。detail 原有签名方式与有效期规则不变。

处理上限仍为 8 MiB：每块在进入摘要之前检查累计大小，越界块不参与摘要，立即销毁请求/响应；不累积整份文件。Content-Length 只作预检，存在时必须合法且与最终实收一致，实际字节始终单独计数。这个上限约束应用摘要处理量；Node/TLS/内核仍可能预读一个块及缓冲，不能理解为网卡恰好只接收 8 MiB。

从 handler 入口记录开始时间，仅使用第二个可信 runtime context 的 `time_limit_in_ms` 正安全整数，取值至多 20,000ms；缺失或无效回退目前核实的 3,000ms。平台字段来源为 [腾讯云 SCF Context 说明](https://cloud.tencent.com/document/product/583/9694)。预留量为 `min(1000, floor(limit/4))`，读取的绝对截止时间为 `startedAt + min(15000, limit-reserve)`；例如 3 秒配置的读取软预算是 2,250ms。客户端 event 中同名字段无效。签名等待、引用查询和流读取共用该截止时间，持续滴流不会续期；激活事务首次发起及冲突重试之前也检查截止时间。

上述数字是保守软策略，未经性能实测，不能作为 SLA。签名超时后不再启动 GET，并持续接住迟到失败；已经发出的 SDK 签名或数据库 RPC 无法真正撤销，已在执行的事务不能声称被取消。当前线上 3 秒硬超时的调整由部署负责人另行处理，本代码没有变更运行配置。

shareStatus 先验证数据库大小为 1..8MiB 的安全整数及合法 SHA-1，再签名。只有无矛盾的 SDK typed 缺失才返回 missing；只有协议可靠、完整的内容与合法元数据不符才返回 invalid。超限、权限、HTTP 404、压缩、截断、畸形签名和超时均返回 SHARE_STATUS_UNAVAILABLE，保留本机引用和录音，不自动重传。commit 的超限/明确缺失/完整不匹配映射为现有 RECORDING_FILE_MISMATCH，超时为 ETIMEDOUT，其余为固定 CHECK_IN_ERROR；不激活失败的 pending。

发布时先增量上传 `checkIn/recordingDownload.js` 并确认成功，再上传引用它的 `index.js`；不能并行，也不需要重装依赖。须验证目标是否支持新增文件增量部署，核对两份源码摘要、Nodejs16.13 的实际运行、SDK 真实签名响应、URL 无重定向且返回 identity 字节，以及正常/最大 8MiB 的 commit/shareStatus 冷暖启动总耗时和事务余量。当前本地测试使用 Node24、假的 HTTPS/可控时钟和内存合成录音，证明应用边界与状态映射，不代表 Node16、真实网络格式、线上延迟或 3 秒内完成已经验收。
